1. MEDIUM (claim): "never hides a pair seen through a real opening" holds only above float noise. c1m1 pair
   493-1711 is hidden by merged; `vis_certify -all` gives 5 chains and a stabbing search finds a real line with
   +0.0003 units clearance (chain 2663 2664 2666 2726 3642 3646 4150 4164 4174 4192 4198 4488 6160 6268 8096). Cause:
   hull2 re-rounds hull points to float; g_merge_eps 1e-4 drops points outside the hull. The hlvvis.c argument
   "bigger windows give bigger separator regions" isn't valid for vvis's subset of planes; what holds is that every
   separator of the bigger windows separates the smaller ones, so merged keeps every path's antipenumbra. Done:
   the claim is reworded to "never hides an opening wider than vvis's own 0.01 tolerance". Optional:
   HL_INFLATE=0.005 for a strict guarantee. Keep vis_merged_suite + certify -all + the stabbing search as the
   release gate.
2. LOW: looseness can't blow up in practice: the hull of several paths' windows can span an occluder, but the
   symmetric crosscheck removes it unless both directions are loose (worst row: +12% on one c5m1 cluster; a
   synthetic worst case came out 0.00% looser). Skybox shells, water, fog, detail don't change this.
3. LOW (speed): no regressions from the dirty-sweep fix (0 portals opened fully, ~3 sweep rounds per base portal);
   per-thread memory NPD x PW x 8 bytes (~50 MB/thread on a 20k-portal map), never freed (fine).
4. INFO: zero-area / 2-point hulls flow harmlessly (superset direction); thread safety matches the exact path.
